# Domain docs

## Before exploring code

Read the root `GLOSSARY.md` if it exists, along with the relevant decisions in `docs/adr/`.

If either is absent, continue without calling it out. The `domain-modeling` skill adds these documents when it settles a term or decision.

## Layout

This repository has one domain context. Keep its glossary in the root `GLOSSARY.md` and architecture decisions under `docs/adr/`.

## Use glossary terms

Use the glossary's terms in issue titles, refactor proposals, hypotheses, and test names. If a needed term is missing, note the gap for `domain-modeling`.

## Flag conflicts with decisions

If proposed work conflicts with an ADR, name the ADR and explain why it may need to be revisited.
